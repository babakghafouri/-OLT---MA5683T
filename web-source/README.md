# داشبورد مدرن اپراتور Huawei MA5683T

نسخه وب فارسی RTL با ظاهر مدرن الهام‌گرفته از طرح گرافیکی مورد تأیید، ساخته شده بر پایه کد پنل OLT قبلی.

## شروع سریع در ویندوز

1. فایل ZIP را در یک پوشه استخراج کنید.
2. Python 3.10 یا بالاتر نصب باشد و دسترسی pip داشته باشید.
3. فایل `start_windows.bat` را اجرا کنید؛ یا در همان پوشه اجرا کنید:

   ```bat
   python -m pip install -r requirements.txt
   python app.py
   ```

4. در مرورگر به `http://127.0.0.1:8080` بروید.
5. روی «اتصال به OLT» بزنید و اطلاعات اتصال را وارد کنید.

در لینوکس/macOS نیز پس از `pip install -r requirements.txt` دستور `python app.py` اجرا می‌شود.

## امکانات

- منوی کناری تیره، داشبورد شش KPI، شاسی ۱۳ اسلات MA5683T، ظرفیت پورت، وضعیت منابع، پایش نوری، بخش آلارم و دکمه‌های اقدامات سریع.
- شناسایی مدل و نقش کارت‌ها از دستور `display board 0`؛ خروجی واقعی تأییدشده کاربر: کارت‌های GPON در اسلات‌های ۰، ۱، کنترل Standby در ۶، Active در ۷، آپلینک در ۸، ۹.
- بازخوانی مشخصات نسخه و Patch از `display version`، منابع، آلارم و آپلینک با API فقط‌خواندنی `/api/overview`.
- اسکن *اختیاری* پورت‌های انتخابی از API موجود `/api/port`، و نمایش ONT آنلاین/آفلاین **فقط برای پورت‌هایی که با موفقیت اسکن شده‌اند**. برای تغییر لیست پورت‌ها به منوی «پورت‌ها و ONT» بروید.
- مشاهده خروجی خام CLI در تب‌های Inventory، منابع و آلارم‌ها و حفظ منطق ثبت ONT قبلی (`/api/plan` و `/api/apply`).
- تم تیره / روشن و طراحی واکنش‌گرا.

## شفافیت داده‌ها

- در حالت آفلاین، **فقط شاسی و نسخه نرم‌افزار نمونه** بر اساس خروجی متنی OLT ارائه‌شده توسط کاربر نشان داده می‌شود. این داده‌ها زنده نیستند و در پنل صریحاً برچسب پیش‌نمایش دارند.
- مقادیر عددی تصویر مرجع (مانند تعداد ۲۵۶ ONT، ۳ آلارم، CPU ۳۸٪، RAM ۶۱٪، دمای ۴۳ درجه و توان‌های نوری) به‌عنوان اطلاعات واقعی در کد قرار داده نشده‌اند.
- علامت `—` به معنای «ناموجود / تأییدنشده» است، **نه صفر یا سالم بودن**.
- تجمیع نوری سراسری پیاده‌سازی نشده؛ توان نوری هر مشترک از صفحه جزئیات ONT و دستور فعلی verify قابل مشاهده است.
- اسکن پورت‌های انتخابی با درخواست‌های جداگانه به دستگاه انجام می‌شود و ممکن است زمان ببرد؛ این خلاصه جایگزین پایش کل OLT نیست.
- خواندن CPU، Memory، Temperature، Fan، Alarm و Uplink به نسخه و خروجی CLI بستگی دارد. برخی دستورات روی نسخه MA5600V800R013C10/SPC205 ممکن است پشتیبانی نشوند؛ خروجی دستگاه ملاک است. پارسر تنها مقادیری را که با الگوی قابل تشخیص پاسخ دهند نمایش می‌دهد.
- اجرای داشبورد در مرورگر با داده شبیه‌سازی‌شده تست شده؛ **اتصال عملی به OLT واقعی و دستورات دستگاه تست نشده است**.

## امنیت

- بهتر است SSH جایگزین Telnet شود، اگر دستگاه و تنظیمات اجازه می‌دهند. Telnet رمز و اطلاعات را رمزنگاری نمی‌کند.
- به‌طور پیش‌فرض سرور فقط روی `127.0.0.1` است. برای دسترسی در شبکه مدیریت، `HOST` و `UI_PASSWORD` با رمز قوی تنظیم کنید و محدودیت فایروال / VPN را اجرا کنید.
- پنل از یک نشست OLT سراسری استفاده می‌کند و برای استفاده هم‌زمان چند اپراتور/چند OLT طراحی نشده است.
- دستورات ثبت ONT توسط کاربر باید پیش از اعمال بررسی شوند؛ قابلیت ثبت در یک OLT آزمایشی تست شود.

## سازگاری CLI با MA5683T (R013C10 / SPC205)

- وضعیت CPU با شناسایی کنترل‌برد Active از `display board 0` و سپس `display cpu 0/<active-slot>` خوانده می‌شود.
- Resource: دستور `display resource occupancy` بر اساس راهنمای تعاملی همان دستگاه انتخاب شده است؛ تا زمان بررسی خروجی واقعی، هیچ درصدی از آن فرض نمی‌شود.
- دما: `display temperature` (در صورت پشتیبانی).
- وضعیت کارت‌های uplink به صورت خواندنی از `display board 0/8` و `display board 0/9` بررسی می‌شود؛ این اطلاعات جایگزین وضعیت عملیاتی تک‌تک پورت‌ها نیست.
- دستورات نامعتبر `display memory`، `display fan`، و `display port state all` حذف شده‌اند. RAM از `display resource occupancy mem` خوانده می‌شود و وضعیت فن از `display emu` استخراج می‌شود. وضعیت ترافیک Uplink جداگانه از خروجی کارت‌های GICF بررسی می‌شود.
- برای دریافت وضعیت دقیق آپلینک، باید خروجی دستورات interface مربوط به GICF در این نسخه بررسی شود.

## اصلاحات سازگار با MA5683T R013C10 / SPC205 (قرائت 2026-10-29)

دستورات منابع اکنون `display resource occupancy cpu`، `display resource occupancy mem` و `display resource occupancy message` هستند. علاوه بر آن CPU برد کنترل فعال با `display cpu 0/<active-slot>` (اسلات فعال از `display board 0` شناسایی می‌شود) خوانده می‌شود. تمام مقادیر درصدی occupancy گزارش‌شده میانگین ۱۰ دقیقه‌اند. دستور `display temperature` بدون آرگومان ناقص است و در این نسخه تا تأیید نحو دقیق اجرا نمی‌شود. وضعیت فن نیز فعلاً ناشناخته است.

برای Uplink، خروجی `display board 0/8` و `display board 0/9` دریافت و چهار پورت GE به شکل مجزا نمایش داده می‌شوند؛ `active` در ستون Active State به معنای `online` بودن لینک نیست. وضعیت فن از `display emu` خوانده می‌شود؛ در خروجی تأییدشده `ID 0 / Type FAN / State normal` است.

نمونه ارسالی در 2026-10-29 (تنها برای مرجع، نه اعداد زنده): CPU=8%, RAM=86%, System Message=0%, Uplink 0/8/0 online, 0/8/1 offline, 0/9/0 offline, 0/9/1 offline, EMU 0 FAN normal. شاخص‌ها پس از اتصال از OLT خوانده می‌شوند و جایگزین نمونه می‌شوند.


## دمای کارت کنترل فعال

دمای واقعی از دستور `display temperature 0/<active-slot>` خوانده می‌شود. اسلات Active از `display board 0` تشخیص داده می‌شود؛ در خروجی ارسالی نمونه، اسلات 7 مقدار `36C` برگردانده است. داشبورد دما را به‌صورت °C نمایش می‌دهد و هنگام عدم امکان قرائت «—» نشان می‌دهد. این عدد دمای برد است، نه دمای محیط یا کل شاسی.

## اصلاح نمای فن و Uplink

- گیج Uplink اکنون «۱ از ۴» و ۲۵٪ را برای نمونه وضعیت ارسال‌شده نشان می‌دهد، نه «۴ / ۱»؛ در اجرای واقعی از چهار خروجی GE خوانده می‌شود.
- وضعیت هر پورت به‌صورت کارت مجزا با شماره پورت، Online/Offline و Optic Status نمایش داده می‌شود؛ Offline الزاماً خطا نیست.
- فن‌ها از `display emu` خوانده می‌شوند. خروجی `0 FAN normal` به‌صورت «سالم» نمایش داده می‌شود؛ اگر پاسخ غایب یا غیرقابل‌تشخیص باشد، پنل وضعیت را نامشخص نشان می‌دهد.


## وضعیت فن از EMU (تأییدشده توسط خروجی واقعی دستگاه)

- برای MA5683T با MA5600V800R013C10 / SPC205، وضعیت ماژول فن از دستور فقط‌خواندنی `display emu` دریافت می‌شود.
- در خروجی ارسالی، `ID 0  Type FAN  State normal` گزارش شده؛ داشبورد آن را به شکل «فن‌ها: سالم» نشان می‌دهد.
- اگر خروجی EMU در آینده حالت دیگری گزارش کند، متن وضعیت خام نشان داده می‌شود؛ نبود خروجی همچنان «نامشخص» است و سالم فرض نمی‌شود.
